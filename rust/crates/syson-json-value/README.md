# Bounded literal JSON values

`parse(text, limits, cancelled)` returns a private `Literal` containing an ordered literal tree and the exact borrowed input carrier, including whitespace, member order, escape spelling and number spelling. Object keys and string nodes are decoded JSON strings; numbers borrow validated original tokens. Duplicate decoded keys always refuse, including escaped aliases. There is no key-name filter or special treatment of `$serde_json::private::Number`/`RawValue`.

A whole-input lexical preflight checks bytes, depth, value count, key count and scalar-copy charge before owned tree construction. Scalar charge is twice raw key-body bytes (private duplicate-check copy plus retained key), raw value-string body bytes and raw numeric-token bytes; quote delimiters are excluded and escapes remain charged at their source length. This is a conservative requested-copy budget, not allocator overhead or peak RSS. Value/key counts bound structural allocations. Malformed input may hit resource limits before syntax errors; no partial tree escapes any failure.

Strict borrowed `RawValue` syntax validation precedes construction. Only strings use typed `String` decoding. Objects are built literally, never by generic `Value::deserialize`. Lone surrogate escapes refuse rather than being replaced; `StringEncoding` is positionless, while `Syntax` coordinates refer to whole-input validation. Configured depth is capped at256 so recursive construction/conversion/drop cannot grow with arbitrarily deep input; the actual library depth208 is admitted. Hard ceilings are32MiB input,2million values,2million keys and64MiB scalar charge. Defaults allow4MiB input and8MiB scalar charge per call. Aggregate caller limits remain the caller's responsibility.

`Literal::into_value(cancelled)` consumes the admitted tree and returns `(Value, original_carrier)`; statistics remain available on the literal before consumption. Materialized object keys are explicitly lexically sorted even if downstream Cargo feature unification enables serde's order-preserving map. `Value` is a convenience view, not wire/member-order authority. The original raw carrier is not a serialization of later edits. Callers requiring edited persistence must maintain their authoritative wire/carrier rules; generic re-deserialization downstream reintroduces the original bug and must be replaced by adopting this utility.

The exact pinned serde_json1.0.151 `Number::from_string_unchecked` constructor is used only after complete strict syntax validation of immutable input. It is public but doc-hidden; its pinned source proof is retained separately. This preserves `-0`, decimal/exponent spelling and unbounded numeric magnitude without floating-point conversion. The ordinary typed Number parser normalizes some integer spellings and is therefore not used. No unsafe code is present.

Cancellation is checked initially, at most1024source bytes apart in this utility's long token/whitespace scans, between tree nodes and conversion steps, and around library string-decoding/syntax-validation/map-sorting calls. Those bounded library calls are not internally preemptible; this API is not a wall-clock deadline or UI latency guarantee. Fallible Vec reservations return allocation errors, while ordinary standard-library/String/map allocations retain Rust's allocator failure behavior. No output serializer, filesystem, model, library loader or semantic engine is provided.

RR01 is the reusable authority only. Actual model and catalogue adoption belong to RR02/RR03. Tests compare marker objects to manually constructed maps, numeric spelling to source tokens, ordered-tree/raw identity separately from sorted Value order, and exact budget/cancellation/syntax boundaries. No native parser, UI, persistence or full feature parity is claimed here.
