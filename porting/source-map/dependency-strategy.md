# Dependency strategy for a Rust implementation

This is a proposed boundary and evidence queue, not an approved dependency selection or completed implementation. Direct declarations are indexed in `declared-dependencies.jsonl`; exact transitive resolution and licenses are outstanding.

| Upstream dependency/responsibility | Rust disposition and proof required |
| --- | --- |
| Java21, Spring Boot, Reactor and Sirius backend | Replace application/runtime logic in Rust. No Java subprocess, JNI bridge or forwarding service as the implementation. Match HTTP/GraphQL/subscription failure, scheduling, transaction and cancellation behavior using pinned fixtures. |
| EMF/Ecore generated model, Sirius EMF JSON | Use checked-in Ecore as source data for Rust types/metadata and semantic services. A Rust generator is acceptable; generated Java implementation is not. Reimplement reflective access, containment/opposites, derived values, proxies, references, notifications and resource identity. Verify actual wire serializer conventions; Serde defaults alone are insufficient. |
| AQL and semantic services | Rust evaluator preserving supported grammar and model traversal. A reduced query subset must stay visibly unported. No embedded JVM interpreter. |
| ANTLR direct-edit grammar | Treat grammar as source data; produce or write Rust parser with diagnostics and semantic side effects. The existing direct-edit grammar does not replace SysML/Syside parsing. |
| Embedded Syside JS CLI | Replace parsing, validation, AST conversion and name resolution in Rust. No Node invocation, embedded JS engine or bundled `syside-cli.js` execution in product runtime. Keep script unchanged as upstream reference evidence until notice/source review resolves redistribution. |
| React/TypeScript, Sirius widgets, Apollo, Lexical, Xyflow | Rust/WASM implementation with Rust-owned interaction and state. Browser JS bootstrap generated by a Rust/WASM toolchain may bridge Web APIs only; it cannot contain hidden editor/business/parser implementations. Rebuild layout, text editing, command palette, inspectors, forms, tables, query/results, publication and extension behavior. |
| ELK.js/pathfinding/layout and image export | Rust layout/routing/export code or explicitly reviewed Rust libraries. JS calls to these libraries would retain non-Rust application behavior. Compare positions, routes, fonts and exported artifacts against oracle; mark differences explicitly. |
| PostgreSQL15 | External non-Rust service explicitly disclosed, not part of Rust source port. Rust database client/transactions replace Hibernate/Spring persistence. Existing schema compatibility and Liquibase migrations need source/artifact fixtures; no production database access. |
| Browser/OS/fonts/TLS/compression/system libraries | External platform dependencies must be listed per selected target. Pure Rust source does not imply Rust browser, OS or font implementation. Review native build/link dependencies and distinguish development tools from runtime. No replacement packages selected here. |
| Tests/build/docs tooling | Java, Node, Maven, Cypress, Playwright or browsers may be isolated reference/test tools; they cannot become hidden product runtime. Inspect scripts and obtain action-specific permission where required before execution. Reproducible Rust checks require pinned lockfile, toolchain and target definitions. |

## Notices and provenance

Root `NOTICE` declares EPL-2.0 for the project and LGPL-3.0-only for the standard libraries under `backend/application/syson-application-configuration/src/main/resources/kerml.libraries` and `sysml.libraries`. Root `LICENSE` and `LICENSE-LGPL` contain the actual texts; leave them and original headers/history intact. A port does not erase upstream authorship or redistribution conditions. Preserve these files and the corresponding notices with distributions containing their material. Do not replace obligations with a credit line or relicense copied assets/generated transformations by assumption.

`license-evidence.jsonl` inventories verbatim declaration locations and hashes. It does not resolve every bundled component, font/image license or transitive dependency. The bundled `syside-cli.js` contains third-party source/license material requiring a separate provenance review beyond root SPDX detection. Unmarked files and generated code require provenance review; absence of an SPDX marker is not a license conclusion. Preserve all source notices and record modifications with chosen artifact/dependency review before distribution. This inventory makes no legal-clearance claim.

## Proposed shared contracts

- Domain lane: stable element IDs and canonical classifier names from Ecore, containment and non-containment references, transaction boundary, diagnostics and explicit operation errors. Unknown/unimplemented semantics must return a visible error, not silent success.
- Frontend lane: commands target stable element/representation IDs; invalid textual drafts remain local until accepted; each mutation has explicit revision/result/error. Selection, viewport and visual representation state stay distinct from semantic model state.
- Compatibility lane: pin UUID/nameUUIDFromBytes behavior, serialized field omission and reference shape, import/export data, project/library archive format, migrations and recovery. Do not invent wire schema before fixture review.
- Validation lane: maintain baseline-to-Rust test mapping by file/feature IDs, differential fixtures for errors and roundtrips, independent accessibility/graphical workflow evidence. Test names, source hashes and successful compilation do not establish feature parity.
