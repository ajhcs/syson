# Rust parser replacement contract proposal

This is a source-grounded implementation strategy for the entire candidate Syside parser/import path. No Rust parser is implemented or accepted by this document. Intended source candidate is Syside `0.9.0` (`1326f234cae23b0e4777d5a48a069b17e9e332f1`); its declared standard-library version is `2024-12`. That scope is distinct from implementing the latest SysML standard and from proving the exact provenance of SysON's embedded bundle. Preserve observed upstream quirks until an explicit compatibility decision is made.

All Syside paths below are under `packages/syside-languageserver/` unless stated otherwise. The exact sources, rule declarations and original source candidates are retained by the accompanying indexes.

The candidate lockfile declares Langium `1.2.1`, whose dependency block uses Chevrotain `10.4.2` with `chevrotain-allstar 0.1.7`; the language-server also has a separate direct Chevrotain `9.1.0` declaration. These are source lockfile claims, not installed/baseline artifact proof. Preserve the actual selected parsing/lookahead semantics rather than silently substituting one version. `parser-dependency-source-documents.jsonl` retains the exact package/lock/config source; generated grammar header identifies `langium-cli 1.2.1`. `langium-config.json` enables recovery and sets `nodeLocationTracking` to `none`; custom CST and LSP ranges still exist. A Rust port must establish effective token/range behavior rather than infer that locations are absent. JavaScript/TypeScript strings and LSP positions require explicit UTF-16/UTF-8 boundary handling in Rust, especially supplementary characters and invalid input.

## Implementation sequence and independently buildable contracts

1. **Freeze declaration inputs and provenance.** Consume the complete retained Grammar JSON and original `.langium` sources as data. Define a Rust-owned grammar IR with every observed node kind and reference/cardinality/assignment attribute represented; reject unknown constructs during generation. Prove every one of the 735 per-language rules maps to IR or an explicit blocker. Do not execute Langium/TypeScript as a hidden build/runtime requirement.
2. **Select the Rust parsing engine after equivalence experiments.** A Rust-only generated parser or Rust interpreter over the pinned grammar IR is acceptable in principle. Selection must handle actual lookahead/ambiguity, ordered token definitions, actions, fragments, recursion, recovery and cancellation; a small handwritten SysML subset is not a substitute. No existing Rust library is selected or assumed sufficient here. Record native/WASM constraints and all transitive/runtime licenses before acceptance.
3. **Implement tokenization/CST and complete syntactic coverage.** Keep token text and byte/UTF-16 ranges separate from converted values. Port all 12 per-language terminal definitions, hidden tokens and compound terminal calls, then all parser rules in dependency order with strongly connected components handled explicitly. Preserve source order and retain malformed-input diagnostics. Source-extraction counts alone do not qualify any rule.
4. **Implement AST/reflection and postprocessing.** Translate actions, assignments, type hierarchies, mandatory defaults and every postparse repair before claiming AST compatibility. Keep syntax, semantic metamodel and persisted Ecore identities as explicit layers with checked adapters.
5. **Implement names/workspace/semantic/validation layers.** Port import/export indexes, scope/linking, implicit semantic construction and all registered validation checks with library inputs frozen. Add cancellation and diagnostic ordering evidence. Do not silently resolve missing names or invent omitted standard-library types.
6. **Implement SysON AST serialization and translation.** Match actual CLI JSON shape and error surfaces, then feed the native Rust domain/persistence layer through the full translation contracts. Replace both textual model import and expression editing/validation. No Node subprocess, JS engine, Java service or TypeScript implementation may supply hidden application semantics.
7. **Qualify complete workflows.** With an approved upstream oracle, compare both grammars' positive/negative fixtures, comment/name/number/unicode cases, error recovery, import cycles/aliases/visibility, expression scopes, postprocessing, validation, cancellation/retry, repeated builds and text/model/archive roundtrips. Compare data artifacts and realistic model creation independently of a browser front end. The oracle has not run in this audit.

A proposed Rust API should explicitly distinguish language, parse/build/validate modes, frozen library set, diagnostic/result state and cancellation. Parsing, linking, validation and SysON import must not collapse into a boolean success result. Resource limits and recovery behavior need observed compatibility decisions, not arbitrary defaults. This is an integration proposal, not a currently shared or accepted API.

## Complete-declaration and runtime acceptance gates

The declaration index is structurally complete for the two serialized candidate grammars: every top-level rule and interface/type entry is retained, all local grammar references resolve, and original declaration candidates exist for every rule. This limited statement does not prove that the candidate matches the embedded SysON binary, that the grammar represents the latest standard, or that the full parser/semantic implementation has been ported.

Runtime closure requires a per-rule/semantic-check ledger with Rust implementation references, positive and negative fixtures, parser/build/validation diagnostics, oracle result hashes and independent review. Shared per-language rules may be deduplicated in Rust only after proving semantics remain identical. All 735 current rule entries remain explicitly `UNPORTED`; the source audit never turns them green. Full notice/source/build provenance and exact matching SysON CLI bundle/license coverage also remain OPEN.
