# F19B: cooperative canvas publication and persistence

This stage adds a controller over the real F19A geometry functions. It does not wire App actions or the loader yet; the dependent rendered stage completes that journey in this batch.

A request captures the canonical committed model JSON, explicit label observations, selected IDs and a monotonically increasing string ticket scoped to one controller instance. The App retains that instance across document imports. Computation and publication are distinct calls. Superseded/cancelled tokens cannot compute or publish, duplicate completion cannot create extra history, and publication independently compares the exact canonical model bytes. The calling App must invalidate on model, selection and font-generation changes even when serialized model bytes happen to repeat. This is a proposed cooperative protocol, not an off-main-thread worker or preemptive CPU cancellation contract.

Full layout runs the real bounded geometry composition. Rotation applies the existing prepare_rotation, computed layout and finish_rotation functions: only the first selected leaf swaps dimensions, selected nodes and their incident edges adopt computed results, and unselected nodes/edges retain prepared data. Nonleaf-container rotation is outside this finite family. Unselected parents can remain too small after selective rotation; explicit full layout recomputes package bounds. No arbitrary post-merge obstacle/containment optimality is claimed.

Canvas undo/redo is separate from semantic model history and retains at most32 prior frames. Model invalidation clears canvas geometry/history. Selection/font cancellation preserves already-published geometry but rejects queued work. Scene reads, history and export remain tied to the supplied committed document. Request snapshots are bounded to1MiB and32 selections; identity counters fail closed rather than wrapping.

The companion JSON is a new local canvas format, not native EMF model JSON or a SysON archive. It stores a version, the exact canonical committed document string, node geometry and typed edge routes. Import derives expected node/parent/typing identities directly from that document; it does not fabricate a DOM observation or run F15 measurement. Unknown fields are rejected. Duplicate/unknown/missing IDs, wrong versions/model bindings, noninteger or nonfinite node/header data, bounds failures and invalid half-unit orthogonal route endpoints fail before mutating current geometry, history or pending work.

Before publication or successful import, one canonical encoder checks both the companion file limit of1MiB and its JSON-string representation plus2048 reserved bytes for default ABI framing/entropy against the same1MiB limit. Escaped model strings can exceed the latter budget even when the model and file fit separately. Oversized computed results discard pending work while preserving published geometry/history; oversized imports preserve pending work too. Only admitted frames enter history or export. Larger custom ABI budgets are outside this default-ABI canvas contract.

Imported geometry is caller/file data. Schema/identity checks do not attest that it was freshly measured, freshly computed, obstacle optimal or native-runtime qualified. Semantic model bytes are unchanged by canvas operations. Original execution evidence and exact input hashes are retained under validation once coordinator checks complete.
