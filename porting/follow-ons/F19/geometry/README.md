# F19A: bounded canvas geometry composition

This stage adds a public geometry API to the existing WASM/native crate. It combines the already-pinned F15 leaf measurement, F18 package forest and F17 sibling routing APIs. It does not wire an App control, publish asynchronous work, store history or claim native rendering parity; those are separate dependent stages completed in this batch.

`measured(document, observations, epoch, previous)` accepts explicit name-label bounds keyed by stable element IDs. These are caller observations, not evidence that Rust read the DOM. Supported nodes are exact Package, PartDefinition and PartUsage classes; their semantic owners must be Package nodes. FeatureTyping endpoints must be supported, same-parent PartUsage and PartDefinition nodes. Other model element classes are rejected rather than silently omitted; unsupported families fail without a returned partial scene.

All leaf rectangles use the F15 package-leaf formula. Applying that envelope to part rectangles is an explicit proposed canvas policy, not an upstream Part renderer port. Previous user-resized leaf dimensions feed the real F15 previous-size branch. The host bounds cover the name-only 14px / 24px label. Header footprint is the ceiled name height plus a fixed 20px class-caption row, an explicit canvas policy; whole-pixel admission is also a canvas policy; geometry and routing remain finite candidates. Full layout applies F18 fresh placement to each sibling group. A leaf-rotation computation retains unselected relative positions before calling F18 and F17, so later selective publication can retain existing endpoint locations.

The owning container rectangle is excluded from its child sibling router; child package rectangles remain obstacles/endpoints in their own sibling group. Prior route buffers are deliberately ignored and recomputed rather than copied; they are not inputs to fresh routing. The computed result requires finite nonnegative integer rectangles within the router bounds. Fractional layout is refused instead of silently rounding a route into apparent correctness. Routes retain zero clearance and may touch boundaries; no ELK, native diagram, full container or crossing-optimality claim is made.

The API admits at most 32 nodes and 64 typing edges. Nonempty connection handles (ports), more than 32 selection entries, invalid IDs, owners, endpoints, sizes, duplicate identities, unsupported parent/typing families, missing observations and geometry limits return errors. Logical budgets and fallible guards in the constituent algorithms do not guarantee a process RSS or wall-clock ceiling. Tests exercise real F15/F18/F17 computation and independent route endpoint/interior and package containment checks, rather than identity-layout stubs.

The source manifest pins exact prerequisite blobs. Original source provenance and qualifications remain in the inherited F15/F17/F18 packets. No upstream Java/TypeScript runtime is executed by this stage.
