# F47: selected namespace containment and part typing validation

This crate freezes two current upstream rule expressions: `validateNamespaceDistinguishibility` (the source spelling) and `validatePartUsagePartDefinition`. The finite class whitelist is Package, PartDefinition, PartUsage, OwningMembership, FeatureMembership and FeatureTyping. This decision boundary was inspected before implementation and sent to the coordinator before manifest preparation. Rules retain upstream warning severity. There is no all-rules-valid flag: reports list only requested, applicable checks; empty applicability is an explicit empty list. An unknown requested rule refuses the whole request.

The validator constructs the actual F11 AST and pairs its declaration preorder with selected-model preorder. It requires equal declaration count, exact class, the same F14 cleaned declared name and the same semantic parent through actual F46 owner queries. Duplicate equal-name declarations remain source-order observations, without claiming unique native source identities. Extra classifiers, root non-Packages, additional containment channels, multi-member memberships, fields outside the per-class finite projection and misplaced typing refuse. Each FeatureTyping must explicitly name its containing PartUsage semantic ID in typedFeature. This is a checked caller source association, not a native parser/source-map attestation. Data such as short names and typing may change between source and model; the source locates declaration identity and the model supplies values being checked.

The namespace rule applies to all three admitted Namespace subclasses. Actual F46 owned-element/name operations project the sole owned member of each admitted membership. Pairwise class compatibility uses actual metamodel equality/subtyping, and primary/short names are compared in both directions. Repeated names in unrelated scopes and equal names on incompatible classes do not conflict. The part rule follows only direct owned FeatureTyping relationships, ignores absent/null types and passes when at least one target is a PartDefinition. It preserves F14's explicit **local semantic-ID** encoding: node IDs never act as fallback identities. Unresolved IDs, external encodings and nonstring references refuse instead of becoming clean or invalid-rule results. Native EMF node-ID wires require a separate adapter.

Failed selected checks return semantic element ID, actual F46 qualified name, warning severity and actual F11 half-open UTF-8/UTF-16 declaration spans, plus one-based line/UTF-16 column. CRLF counts as one line break, and bare CR or LF each count as one; columns count UTF-16 code units after the latest break. The source-position audit follow-up extends the original LF-only policy without changing declaration spans. This local position policy does not attest native LSP newline equivalence. The immutable API writes no document/editor/history. Cancellation and unsupported inputs return no partial report. Bounds reuse F11's default 65,536-byte/256-declaration/32-depth policy and add 2,048 selected document objects; these are local admission limits.

The finite regression set integrates the actual F14 importer and F46 semantics, then tests edited/malformed selected projections. Source pins qualify the inspected source, not AQL execution. Full SysML constraints, native parser/import/serializer behavior, native diagnostic formatting/order, effective Spring providers, all subclasses, external resource loading and engineering conformance remain unqualified. The native synthetic root Namespace is not modeled; only real root Packages are admitted. Parser errors retain the F11 error family. The frozen source whitelist does not imply complete feature parity.

Dependencies are F14 #52 and F46 #49. This PR targets an immutable exact-blob snapshot of both prerequisites; land them first, retarget to integration, inspect the resulting diff and revalidate. Never merge into the snapshot. Existing held model/graph/factory paths are unchanged. Coordinator-only offline checks, receipts and review are recorded in VALIDATION.json after execution.
