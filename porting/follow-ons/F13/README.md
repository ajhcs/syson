# F13: finite local ElementReference chains

The standalone `syson-linker` crate separates immutable syntax from linked outcomes. It consumes an owned F11 arena and traverses its admitted Namespace/package/part declarations through their source-shaped membership wrappers. F11 TypeReference is an ElementReference subtype; the parser's unresolved part markers remain unchanged. Name sanitization follows the selected candidate source's quote/escape behavior. The first segment searches the nearest lexical declaration scope and its parents; later segments search only the prior resolved element's local scope. Failed lookup retains the successfully found prefix. A wrong-type candidate is retained in `found` but never becomes the final target.

The admitted AST family has owned local declarations only. Imports, inherited scopes, visibility expansion, feature chaining, specialization, completion scopes, global libraries and native caches are excluded. Equal sanitized names within a scope refuse admission as ambiguous; this finite policy does not implement the candidate's complete shadow/prune/redefinition model. Named scope export and resolution remain exact-case.

F11 does not parse aliases. `Alias` records are explicit caller-supplied observations of visible local aliases, bound to a scope NodeId from this exact arena. Each carries a raw name and raw target segments. They do not attest native visibility or alias syntax. Alias following resolves from the alias's observed scope, detects cycles and preserves unresolved/type-mismatch results. Duplicate aliases or alias/declaration name collisions refuse admission. Declaration count, alias count, chain length, name length and total lookup work have explicit proposed limits; these limits are not source language limits.

A successful `Link` contains AST NodeIds, never semantic IDs. Semantic lookup is a separate operation that requires an explicit declaration-to-local-JSON-node UUID `Binding`. It uses the actual F04 Registry, preserves resource key, JSON node ID and semantic elementId, and checks the semantic object's metamodel assignability to the syntax declaration's class. Missing bindings and wrong identity/type mappings remain errors. A bare semantic elementId never falls back to the document's JSON node identity. External URI/proxy binding forms are rejected for this local family. Syntax NodeId values are never converted into semantic IDs.

Snapshot ownership is immutable. A private process-local identity on Link refuses replay against another Snapshot, even for identical text and documents; F04 independently rejects semantic targets from another registry. No AST field, semantic document, resource, reference cache or external state is mutated. `semantic()` and `value()` require these local snapshot checks; this is a read-only result API, not a native reference assignment or model import.

The source pins retain the candidate Syside commit `1326f234cae23b0e4777d5a48a069b17e9e332f1`, selected linker/scope/naming/reference-meta source bytes and exact F11/F04 dependency implementations. Candidate source and static tests do not prove correspondence to SysON's embedded CLI artifact. `check_sources.py` reads only existing retained files and Git objects. No upstream parser, native EMF runtime, library loader or oracle was run.
