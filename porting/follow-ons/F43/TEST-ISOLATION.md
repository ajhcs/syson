# F43 fixture isolation correction

The original F43 captures passed on the pinned checkout. A subsequent integration audit found that the unittest fixture builder read the current checkout's Rust source bytes against the policy's fixed `ad814c232ee24109639c1d52239cbeec6f4a3e92` hashes. Composing an independently changed domain crate therefore broke these fixture tests even though the production verifier correctly rejects stale source against an old policy.

The tests now materialize every entry in `policy.source_sha256` directly from `policy.source_revision` Git blobs into the test-owned TemporaryDirectory and verify every hash before writing the fixture file. Both profile package builders, the default verification source and deliberately copied negative-test sources use that snapshot. The symlink and existing-output cases also reference the isolated snapshot. The current checkout is used only as the existing Git object store and location of the admitted tool/policy/capture inputs; no live source file, Git ref/worktree, policy, capture, verifier or fixture-builder production behavior changes.

The same19 behavioral tests remain. Original captures retain their original test-source attribution; no prior pass is relabeled as execution of this correction. The coordinator reproduced the original setup failure in the synthetic nine-PR source composition: the strict production verifier rejected the changed domain module export against the baseline policy before any behavioral test ran. Original streams are retained; the reproduction harness stopped before serializing its initial execution UTC, so execution UTC is explicitly NOT_RETAINED and is not retroactively inferred. The corrected test source then passed all 19 tests in the same composition. The combined F44/F45 domain suite also passed all 62 tests and Clippy. [VALIDATION.json](VALIDATION.json) and [the composition input/overlay index](validation/composition/composition-inputs.json) link exact source heads, reviewed overlay hash, original failure/success streams and scope. These runs qualify only the exercised fixture/domain combinations, not all nine application features or upstream runtime parity. Actual supplied distributions with changed source still require an explicitly reviewed new policy/capture; the strict production rejection has not been weakened.
