# F43: distribution dependency and notice-closure verification

Implementation: `porting/distribution-check/check.py` and `make_fixture.py`, Python stdlib only. Scope: the actual pinned Rust/WASM default/candidate source-bundle inputs and synthetic positive/negative package fixtures. The coordinator's original metadata captures remain unchanged. No Cargo/compiler/build/registry/network execution was performed by the implementation worker.

The captured normal runtime graph has five registry crates in both profiles; default has five local crates and candidate has nine. The verifier requires real packaged notice/license/source/lock/manifest/archive bytes matching the explicit policy, including locked archive checksums. It rejects missing or modified notices/licenses, source or lock mismatch, unknown active dependencies, symlinks and unlisted payload. It distinguishes an accepted supplied capture/package from unresolved source-to-WASM build provenance and legal clearance.

The coordinator's first actual capture (`f43-01`) passed all 19 source-backed synthetic package tests with source unchanged during that run. That historical success applies to the generator bytes before the later explicit (optimization-safe) source-revision guard. The new guard replaces an assert with a ValueError; fresh final verification is pending and no second-run result is claimed here. No upstream application, built-WASM, browser or legal-acceptance test was run. Synthetic artifacts are explicitly labeled and never presented as built application outputs. Existing actual registry archives are caller-supplied test inputs, not new packages or committed binaries. The five manifest fixture bytes match the existing admitted source-manifest SHA256 values in `rust/third-party/manifest.json`. See the tool README for input layout, commands and limits.
