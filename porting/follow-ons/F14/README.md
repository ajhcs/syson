# F14: finite atomic package/part text import

The adapter composes the actual F11 finite text constructor, F13 local linker and F04 explicit resource registry with the existing selected-model transaction API. Its parser limits remain those of F11. The input's synthetic Namespace is not imported as a model object. Named Package, PartDefinition and typed PartUsage declarations are created in source order; typing runs after all declarations exist, allowing forward and qualified references among newly imported declarations. No existing model symbols are injected into the AST scope.

`Importer::stage` consumes one caller-owned Transaction and a caller-supplied NodeIds iterator. Distinct semantic element IDs and JSON node IDs remain separate. Root packages can be attached at document root; top-level parts require an explicit existing package/part parent. Nested creation uses the real model constructors and their selected containment-membership policy. Unnamed declarations, broader grammar, imports/aliases and unresolved or wrong-type references refuse. Identity providers are caller data: UUID spelling/collision checks do not prove entropy, freshness or native factory provenance. IDs consumed before a refusal or cancellation remain consumed in the caller's iterator.

Each declaration gets an explicit AST-node-to-JSON-node binding. The F13 linker owns the unchanged F11 Arena, and F04 resolves those exact node UUIDs against the staged Document. Only then does the importer call `Transaction::type_part_usage`. That existing selected-model API writes `type` and `typedFeature` as semantic elementId strings. It is a different admitted encoding from F04's native bare-string JSON-node references; the adapter does not reinterpret them or claim complete native EMF wire interchange.

The current Java import attribute chain is pinned from `SysideSysMLTextImporter` through ASTTransformer, AstTreeParser, EAttributeHandler and EAttributeTranslator. For string attributes its `asCleanedText` removes every apostrophe. The finite adapter retains that selected declaredName translation, including retained backslashes in an escaped apostrophe such as `W\'heel` becoming `W\heel`. AST reference lookup still uses F13's independent name sanitization and explicit identity binding; transformed model labels are never used to invent lookup keys. Source inspection establishes this finite proposal; no native parser/importer execution has qualified the behavior.

Staging exposes only an immutable preview. Explicit cancel drops the transaction. The commit wrapper rechecks cancellation and delegates to the existing Editor, preserving foreign/stale/failed transaction checks and one undo entry. Parse diagnostics, invalid suffixes, linker errors, exhausted or colliding identities and late typing/cancellation errors return no transaction or partial prefix for publication. Model history changes only on the caller's successful commit. The adapter does not add persistent storage, native reference assignment, broad semantic validation or complete SysML/KerML import.

The branch is stacked on F13, which already contains the exact F11 prerequisite blobs. Land prerequisites, retarget to integration, inspect the resulting diff and run appropriate checks. Do not merge a child into a prerequisite feature branch. No held initializer-graph, factory, admission, backlog or shared manifest path is changed.

The first coordinator capture compiled and ran thirteen tests: ten passed, while three fixture expectations failed. One fixture used an untyped part outside F11's admitted family, one used the reserved `item` token, and a negative fixture conflated parser refusal with importer admission refusal. Those original executed sources, runner and four command streams remain under `validation/f14-01/`. The subsequent test-only corrections use admitted typed declarations and assert each error family; they do not change production behavior.
