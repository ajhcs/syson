# F36: bounded property-inspector keyboard and accessibility qualification

The flow under test is: the local editor loads, keyboard creation commits a package/definition/typed usage, keyboard selection opens the usage inspector, then rename and boolean-property staging are cancelled or committed with origin focus restored and the persistent status updated.

The existing whole-root repaint discarded focus when controls had no IDs and recreated the status node on every action. A small Rust policy now names the next focus target after selection/staging/commit/cancel/import. The loader applies that cue only for manual actions and retains its original background draft, caret, focus and open-details behavior. Stable IDs support ordinary focus restoration; creation, rename and property forms have explicit accessible names, while existing control labels remain intact.

The status paragraph remains continuously connected as a direct child of the editor root. Detached templates replace its siblings, and only changed attributes/text are applied to the existing paragraph. Successful messages retain status/polite/atomic semantics. Error messages retain the existing alert behavior with assertive delivery. This binds DOM live-region updates; it does not establish what any screen reader speaks. Consecutive identical status text is not forced into a new artificial announcement.

The new validation script uses actual keyboard arrows, Tab/Shift+Tab, text entry and Enter. It checks semantic-export isolation before commit, cancel/commit focus return for rename and a typed boolean, labels and live/focused properties in the full Chromium accessibility tree through CDP. A DOM observer checks that the status object is never removed and live attributes remain present. Original authoring, scalar and canvas journeys remain unchanged. Browser plugin not available; installed regular Playwright is the recorded fallback, with service workers blocked and requests restricted to the captured loopback origin.

Root runs native tests, release WASM and browser checks only after the source freeze. Screenshots and full accessibility trees belong outside the repository; the scoped validation packet retains their source-bound hashes and command/stream receipts. No worker compiler, browser, server or upstream application is run.

The five source pins separate the native application/dependency/custom-label source from the exact local F19C inspector and repaint baseline. Inherited Sirius Web inspector implementation and assistive speech are not exercised. Read-only executable probes for orca, espeak-ng, speech-dispatcher and accerciser found none on this session's PATH; this is not a host-wide absence claim. No software or service was installed. Whole-app accessibility, all browsers/platforms, native SysON UI equivalence and screen-reader acceptance remain unqualified.
