# F44 Java-compatible name boundaries

Sixteen new source-derived regression functions qualify the existing names adapter across Unicode stripping, optional quotes, UTF-16 escaping, literal qualified splitting and alias identity. No executable divergence was established in its documented valid-Unicode-scalar input domain, so names.rs is unchanged. These fixtures are not captured Java outputs and do not establish upstream runtime parity.

The source freeze is SysON `6ba2ac64e6b16ee2b05752ad55395eebb87d4910`. SOURCE-CONTRACT.json records six exact Java/pom source hashes and the unchanged names.rs hash from `ad814c232`. The actual ElementUtil method strips candidate and query for direct comparison, but detects optional outer query quotes before stripping. Whitespace outside a quoted query therefore differs from whitespace inside the literal candidate. Matching is asymmetric and preserves exact case, combining sequences and code points.

The [Java 21 Character contract](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Character.html#isWhitespace(int)) supplies the finite whitespace expectations: 25 included scalars and excluded nonbreaking/format/control boundary cases. This uses the target Java API contract rather than Rust char::is_whitespace. No Java executable was invoked.

NameHelper uses ASCII printable-identifier rules, literal `::` splitting and paired outer apostrophe removal. Its escaping option inserts backslashes before apostrophes; optional-quote matching does not decode those backslashes. Printable-name escaping followed by matching is therefore not universally a round trip, and this work preserves that source behavior.

The [declared Commons Text 1.10.0 escape aggregate](https://raw.githubusercontent.com/apache/commons-text/rel/commons-text-1.10.0/src/main/java/org/apache/commons/text/StringEscapeUtils.java) retains DEL, uses Java control escape names and selects Unicode escaping outside the inclusive ASCII bounds. New fixtures cover controls, quotes/slashes/backslashes, BMP values, supplementary pairs and U+10FFFF. Complete subordinate source/artifact correspondence and actual Java runtime execution remain unqualified; the static source reference is not a resolved dependency acceptance claim.

NameConflictingFilter compares alias/name object references before choosing alias-only versus member-name/short-name checking. Rust callers supply that identity distinction explicitly; tests show equal text with distinct identity leaves the short name free, while the same reference reserves it. The filter uses raw exact strings with no stripping, normalization or quote removal. Failure on a short name retains the long-name insertion; failure on a long name short-circuits the short name. Orphan aliases and null names reserve nothing; the empty string does reserve a name.

Existing &str APIs cannot express isolated Java surrogate code units; they remain an explicit unsupported input domain. Native effective-name evaluation, import visibility, subclass getters and model/application conformance remain separate. No new dependency, manifest or lockfile was added.
