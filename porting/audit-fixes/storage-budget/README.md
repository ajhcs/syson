# Bound aggregate storage serialization

The F27 API admits up to 64 changes with a 1 MiB limit per serialized document. The original request limit of 8 MiB is checked only after all documents, operation values and the final protocol packet have been materialized. A single near-limit document borrowed by 64 valid create changes therefore causes avoidable allocation before the request is refused.

`examples/storage_budget.rs` is the fixed before/after API probe. The coordinator must supply one fresh absolute database path. It creates that owned candidate store, records the initialized database bytes, reuses one 1,048,448-byte document in 64 distinct-key creates, then requires `Error::Limit` and byte-identical database state. No fallback path, cleanup, arbitrary SQL, network or native PostgreSQL operation is added. The unchanged bridge performs the existing candidate initialization only; the oversized transaction must refuse before invoking it.

The coordinator built first, then measured the actual release example binary with `/usr/bin/time -v` so maximum RSS excludes Rust compilation. The same frozen probe passed before and after, each returning the aggregate limit error with byte-identical initialized database state. Maximum command RSS decreased from 267,536 KiB (261.3 MiB) to 13,332 KiB (13.0 MiB), about 95.0% lower. `memory-summary.json` records the exact observations, binary/probe/raw-stream hashes and retained external database hashes. This is one before/after workload, not a percentile or native PostgreSQL comparison. SQLite binaries remain external.

The repair streams operation serialization into a bounded complete request instead of collecting every serialized document and repeatedly cloning a full JSON value packet. The writer grows geometrically while capping its reserved capacity at the declared byte budget; only one current operation is retained. Content moves into the operation value rather than cloning a batch. The bridge is invoked only after all JSON delimiters fit and the packet is complete. JSON names/content remain encoded by serde_json. Per-document writer refusal remains `Serialization`; aggregate protocol exhaustion remains `Limit`. The first reached aggregate limit stops serialization; later invalid batch items are not inspected. No bridge, schema, tool or dependency changed. The coordinator's `store-01` capture passes all 17 tests (2 pure budget tests and 15 integration cases), formatting, all-target Clippy and the release example build. New regressions cover allocation capacity, escaped JSON/final-delimiter bytes, 64-operation aggregate refusal without database mutation and successful 64-operation escaped name/document round-tripping. The original serializer and late SQL rollback cases remain separate and pass. Exact runner, streams and executed input snapshots are retained.

This change stays within the local selected-JSON SQLite candidate. It does not implement native PostgreSQL persistence, authorization, crash durability or complete source/artifact correspondence.
