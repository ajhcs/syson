# Fixed unsigned RR13 registration candidates

This preparation library constructs unsigned data for RR13a/RR13b. Its immutable 1.0.9 baseline has 792 units/1584 typed nodes and 55 historical records; current registration and generated adoption are separate root-reviewed steps. Default library/driver imports read no application files.
`derive(files)` accepts an explicit relative-name→bytes map containing the pinned complete baseline, all old contract inputs, six preserved policies and the proposed storage lane/template/amendment. The template must state parent_intent RR13→[RR13a,RR13b]. It returns unsigned policy, expected-plan, contract and schema artifacts, preserving full old records and rebuilding typed edges with an independent cycle check.
`contract_lock(files, old_lock_bytes)` retains every old required path and adds the fixed EXTRA source/input set. Prior arguments enter the aggregate bound before hashing or parsing; the prior/ namespace is reserved. `snapshot(files, old_register_bytes, old_snapshot_lock_bytes, old_contract_lock_bytes, snapshot_id, base_main, progress_inputs=())` preserves every nonderived generated unit field and hashes the complete original plan record, including any source feature_acceptance value. Its five derived columns are primary_family, brief, brief_sha256, complete_plan_unit_sha256 and historical feature_acceptance; absent history yields OPEN_NO_ACCEPTANCE_RECORD even when the plan says OPEN. It preserves current integration attribution, old progress inputs and explicitly added ones.
All functions return UNSEALED_PROPOSAL_ONLY with complete supplied-input SHA-256 bindings. Both derive and snapshot pin the entire historical execution file, including integration and unknown attribution. They never install candidates,seal validators,invoke generators or claim source/feature acceptance. The root separately reviews unsigned actual outputs before any 1.0.10 adoption.
`emit(fresh_path, proposal)` optionally writes only named candidate JSON artifacts plus a source/input/output-bound manifest into a new owned 0700 directory under /workspace/build/builderbob. Existing/symlink/noncanonical outputs refuse. Input bytes plus canonical key/hash metadata and emitted-output framing each have a 64MiB refusal cap; this is not a sandbox or performance guarantee.
Run `python3 -I -B -m unittest discover -s porting/rust-parity-plan-20261026/composition/registration -p test_prepare.py -v` and repeat with `python3 -I -O -B -m unittest discover -s porting/rust-parity-plan-20261026/composition/registration -p test_prepare.py -v`.
Snapshot reuses the complete fixed preparation/whole storage guard after checking actual raw bytes against the supplied map/current lock. Only one strict POLICY_SHA256 literal is normalized for guard code identity; verified actual bytes execute unchanged and cache by raw SHA. A canonical pending guard refuses snapshot; only the root performs the separately reviewed production literal seal.
Tests load old locks/register from the pinned five-file baseline and all 37 normative byte overrides from its compressed capsule, verifying compressed/uncompressed bounds and hashes, exact old-lock coverage and every decoded row length/hash/Git blob. The same three complete captured JSON fixtures remain data-only inputs. A test-only canonical pending guard is normalized from the actual identity-checked guard before constructing a synthetic seal; scoped reads and matching raw-map/lock pins preserve all negative controls after real adoption. Capsule program bytes never execute; tiny synthetic children/amendment/briefs remain unadopted controls.
Tests cover strict finite JSON,complete old record/graph restoration,private results,held inputs, source pins, caps, cycles, exact lock sets, full snapshot fields/progress and real private fresh-output/refusal controls. Tests scope and restore a synthetic sealed guard read with matching raw input/lock pins; they never edit the on-disk guard. Hosted output tests patch only OUTPUT_ROOT to their own admitted runner temporary directory; production has no path override.
Root records source review and actual normal/optimized execution separately; source authoring establishes no passing runtime result. Existing 165-line current-plan storage tests, 191-line draft guard and 252-line landed guard tests retain their own roles; this library does not replace their adoption gates.
Actual RR13 adoption uses the complete source records, independent unsigned-policy review, a real root seal and raw source pin, the module-alias shim, reviewed shared wiring/required inputs, actual build_plan and all-record/edge comparisons, then a verified final snapshot. The fixed driver emits only fresh candidates; DERIVE records captured logical origins and physical reads, while LOCK/SNAPSHOT use current bytes with separate old raw arguments and all five baseline progress paths. Root records adoption separately.
