# Amendment 1.0.8: team ownership and concurrent engineering

Adopt six engineering portfolios and independent verification/release, with a separate integration coordinator. TEAM-EXECUTION.md defines responsibilities and interfaces; teams.json assigns every existing review unit exactly once. Generated team-dispatch.json records every cross-team readiness edge with its implementation/acceptance endpoint types intact.

All 790 units, dependency and readiness edges, source paths, budgets, cases, parent gates, six earlier split policies, legacy budget disposition and 55 historical execution records remain unchanged. Team assignment grants no source lease, runtime admission, held-owner handoff or feature acceptance. Each active PR requires exclusive writable paths, satisfied prerequisites and an independent reviewer. Shared exports, Cargo manifests/locks, routes, schemas, registration and application assembly remain coordinator-owned.

The execution ceiling remains three concurrent source authors plus one coordinator. Compiler, native, database and browser execution stays serialized under reviewed resource allocation. Seven portfolios do not authorize seven processes. Existing factory/raw/initializer holds and frozen #130 registration boundaries remain in force.

The first joint product milestone is create/import → edit → save → page reload → close/reopen → backend restart → fresh inspection, without manual JSON reimport. Each team owns its defects and consuming workflows; independent verification owns acceptance review, not implementation of every repair. Performance ranges and integrity/cancellation/resource requirements remain unchanged.

Smaller feature-specific native reference handoffs are future proposals. This adoption removes no C01/C02 or other prerequisite. Any narrowed implementation gate requires a separate reviewed amendment preserving complete final acceptance.
