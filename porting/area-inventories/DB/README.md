# DB source inventory candidate

This candidate maps29 captured schema documents,28 includes and20 changeSets plus selected persistence/aggregate/repository source candidates. inventory.json records exact source references and nine stable contract groups. schema-declarations.json preserves the include graph and source-level operation summaries. These counts are unlike units, not a feature denominator. No DB client, migration, extension, compiler, server or upstream test was run; no final schema or compatibility PASS is asserted.

The pinned Sirius source remains a dependency candidate with unresolved artifact correspondence. Initial pgcrypto/UUID defaults and later representation/project/library identity changes are declarations, not authorization to install or apply them. DBMS filters, contexts/preconditions, Liquibase history/checksums, transactional behavior and rollback are unexecuted.

Persistence snapshots resources before proxy-loading filters/conversion, requires the resource scheme and all filters, and separately protects existing read-only documents. Resource conversion may skip failed saves, logs resource diagnostics and uses metadata/identity fallbacks. Exact charset, EMF JSON and resolved runtime behavior remain open.

The aggregate document merge uses ID/name/content equality to reuse existing instances/timestamps. Changed same-ID documents are rebuilt with name/content, and removal is detected by ID set. A readOnly-only or domain-URI-only change does not by itself trigger that aggregate update path. Dependency add/remove event conditions also differ. These actual source distinctions must not be silently replaced by an intuitive merge policy.

A proposed pure document-reconciliation planner can isolate some deterministic behavior after exact duplicate/null/identity/API contracts and distinct source review are closed. It would not implement Postgres, repositories, transactional events, serialization, crash recovery or full DB parity. The existing native local snapshots remain credited solely to their own MODEL/UI scope. Full source inventory, independent acceptance and runtime qualification remain open.
