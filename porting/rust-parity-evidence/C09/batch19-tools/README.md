# F11 original parser observations

`construction_oracle.cjs` captures the original Syside parser against the finite-construction corpus. It verifies the pinned bundle and selected original module hashes, then evaluates the byte-identical module prefix before the unique CLI entry boundary. The coordinator supplies absolute paths for the bundle, corpus and a new output file on `/workspace`:

```text
node construction_oracle.cjs ABS_BUNDLE ABS_CORPUS ABS_NEW_OUTPUT
```

The source-traced recipe calls `require_sysml_module().createSysMLServices(require_file_system_provider2().SysMLEmptyFileSystem).SysML.parser.LangiumParser.parse(source)`. Service creation injects and registers the original language services. Parser construction can instantiate original linker, scope, configuration and metamodel service objects; the harness does not call their link/build/validation workflows. Configuration construction calls `updateStandardLibrary`, which is a no-op in the original empty filesystem provider. That provider has no standard-library or extension directory, refuses file reads/script loads, returns an empty directory and reports no files. No connection, workspace initialization or server startup is supplied. The trusted-code VM allows builtin imports and is not a security or OS I/O sandbox.

The corpus has schema version 1 and `cases: [{id, source, category?, expected_restriction?}]`. Sources preserve the original 13 tests' native-comparable program intent: declaration wrappers, membership context, raw qualified names, Unicode spans, anonymous/empty bodies, defaults, order, incomplete input and finite-whitelist refusals. Extra cases cover nested and Unicode-qualified declarations and CRLF. Rust limits, cancellation, immutable ownership and cross-arena handles remain separate controls; parsing their fixture text cannot qualify those policies.

Output contains `cases` and `provenance`. Each case preserves the exact source, actual lexer/parser diagnostic arrays and a `tree` object graph. Every own AST key and descriptor is inventoried, and every data property is retained, including declared names, mandatory booleans, undefined properties, empty arrays, `$children`, `$childIndex` and container links. Arrays retain their indices and `length`; repeated objects and cycles use capture-local `$object` references. Those labels are serialization identities, not native semantic IDs. They must not be treated as stable cross-run IDs or persisted model identities.

References retain `$refText`, `$refNode` and own-key inventories. Accessors are recorded without evaluation, including `ref`, `error` and `$nodeDescription`. The sole AST metadata skip is `$meta`, marked in place with its descriptor and reason because it leads into the external metamodel graph. Unknown structural keys are retained rather than filtered by a whitelist. Original diagnostic objects, tokens, context and resynchronization arrays also receive complete own-data records. Nonfinite numbers and negative zero use binary64 hex tags instead of lossy JSON numbers.

CST records preserve spans, text, ranges, child order, parent/root links, data-backed AST associations and inventories before/after safe span-getter reads. Those reads can populate original range caches, so both inventories remain visible. `CST.element` is never read. Grammar-feature context retains its own keys, descriptors and primitive values; nested grammar-context objects are inventoried without traversing the entire linked grammar. CST/grammar context is distinguished from structural AST data, which is retained in full. A parser or capture exception is recorded separately and never presented as a successful empty tree or an original diagnostic.

The oracle performs no semantic projection to match Rust. Raw trees and inventories must be reviewed for extra, absent and default fields before defining a comparison contract. Native recovered trees remain recovery observations, not accepted models; finite Rust refusals stay explicit. Bundle, module, prefix, corpus, probe, executable, Node/V8 and UTC provenance support this recorded runtime only. They do not bind the deployed Docker runtime, the complete native artifact, source correspondence, importer/UI behavior, resource capacity, persistence, performance or feature acceptance. This preparation contains no executed parser result.
