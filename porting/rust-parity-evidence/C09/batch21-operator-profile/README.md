# F12 API baseline source review and execution handoff

The coordinator has executed the retained baseline and a fresh build from this module. Compilation, execution, fresh outputs, source binding and publication remain coordinator-owned. The binary needs the same candidate `syson-ast`, `syson-ast-adapter` and `serde_json` path/dependency composition as operator-qualification-01. It must not silently use main without F12.

`operator-profile N` accepts only 1..5000 synthetic classification inputs. Setup creates a separate fresh processor/builder, one `OperatorExpression(+)` root and N children with explicit defaulted empty operands and operator `as`. Every actual `apply` must return an insertion without normalization; a successful finish must expose exactly 1+4N nodes. Setup, all-N application and finish have separate timers/counters. The API timer includes actual dispatch, transaction snapshots, implicit-node defaults and field writes; it excludes processor/setup/finish. No JSON or RSS reading occurs before measured snapshots are saved.

The counting System allocator retains monotonic request/requested-byte/free counters and current live bytes. Global peak is monotonic; each phase starts a separate high-water counter at actual live bytes, never zeroing existing allocations. Realloc success accounts old bytes freed and new bytes live; failed realloc retains old live bytes. Request volume, peak requested live memory and Linux process high-water RSS are distinct. Atomics add instrumentation cost, so results are an instrumented API baseline, not bare-library timing or allocator-internal resident memory. RSS is process-wide and includes setup.

Run two warmups and seven measured independent processes at each of 100, 1000 and 5000 input operators, recording all raw rows and min/median/max. Each process recreates identical initial state. Admit ramps progressively under resource ownership; preserve typed failure or timeout receipts. Keep host/build/profile/compiler/config/source/corpus/executable hashes and compiler serialization. Use the existing exact candidate unchanged; do not instrument production or alter limits to obtain a pass. `--cancel-before-apply` provides an actual typed cancellation control: it must retain zero inserted reports and actual Cancelled apply/finish outcomes, not a fabricated capacity result.

There is no corresponding native benchmark yet. Do not report a native speed ratio, event-to-visible latency, p95 from seven samples, UI usability, capacity acceptance or RR08 closure. Source review shows F12's single selected-operation transaction clones the whole kernel State even for an unchanged selected node; the clone's copied bytes are uncharged and not cancellation-polled. Applying N operators can therefore perform quadratic snapshot work. These measurements document that unchanged baseline for RR08's later repair. Actual parser callers, nested rollback/CST restoration, in-copy cancellation and copy charging remain locked RR08 gates. Finite prerequisite publication requires explicit review/disposition of these measured risks, not a hard timing veto or a silent performance waiver.
