The pure `admit` API checks a narrowly defined selected-source-runtime claim against explicitly named `UnverifiedFacts`. It verifies policy relationships among the target revision, artifact/config labels, declared hashes, four selected source paths, nine dependencies, selected compiler/runtime arguments, compiled-class coverage and source-label delta. A consistent claim still returns `POLICY_CONSISTENT_WITH_UNVERIFIED_FACTS`, `file_inspection_performed: false`, `whole_artifact_equivalence: false` and `C01: OPEN`.

Root `c01a-01` passed nine policy regressions, formatting and scoped Clippy on six unchanged inputs. Positive tests explicitly construct synthetic coherent final-review facts; they are not actual artifact, file, Git or native-runtime admission. Independent review found that contradiction before the first root execution, and the core now refuses it. The original review/snapshot/example were not rewritten. A later actual inspection requires a new scoped final review receipt, not relabeling history.
