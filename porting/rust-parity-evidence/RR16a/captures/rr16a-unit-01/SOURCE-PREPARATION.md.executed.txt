## Exact CLI and admission

`python porting/run_integration_checks.py --build-dir ABS_EXISTING_WORKSPACE_PARENT --evidence-dir ABS_NEW_WORKSPACE_DIRECTORY --admission ABS_JSON [--start-at COMMAND_ID]`

Build/evidence paths are resolved through existing parents and both must be outside the candidate. Target is newly created at build-dir/target and reuse refuses. Evidence must not exist. No output falls back to root disk. The resolved script location defines the candidate checkout. An import has no execution side effects; main is guarded.

Admission JSON uses duplicate-free object members and schema `RR16a/1`:

- `candidate`: full40-character committed SHA, matching actual HEAD and index, plus every tracked worktree byte/mode.
- `commands`: nonempty ordered objects with `id`, `kind`, `argv`, `manifest` (repository Cargo path or null), `required_inputs` (repository paths), `required_pins` (declared IDs), `timeout_s` (>0 and <=1800).
- `held_manifests`: repository Cargo path to ownership reason. Hard graph hold and every discovered `rust/validation/factory/` descendant remain held regardless of that map. Standalone syson-initializer itself is not a hard hold.
- `historical_pins`: objects `{id, revision:FULL_SHA, path:REPOSITORY_GIT_PATH, sha256}`. Every required ID must resolve. Actual immutable Git blob bytes are hashed without replacement objects.
- `external_inputs` and `tools`: objects `{path:ABS_REGULAR_NONSYMLINK_FILE, sha256}`. Actual resolved Git and executing Python must be declared; each command argv0 must be declared. Root should declare actual Cargo/rustc/rustdoc/Python/Git identities, not shell aliases.
- `env`: explicit string values only. Supported names are HOME, PATH, CARGO_HOME, RUSTUP_HOME, RUSTC, RUSTDOC, TMPDIR, SYSON_TEST_DIR, SYSON_BUILD_DIR, and owned fixture RR16_* controls. No inherited arbitrary environment is copied into command execution. The existing HOME is retained when supplied; no system/Codex identity is repurposed. Jobs1/target/Python-bytecode and no-replace/global-config Git controls are fixed by the runner.

Supported Cargo argv is exactly `[ABS_CARGO, test|build, --offline, --locked, --jobs, 1, --manifest-path, REPO_MANIFEST]`. Test tail may be empty or `-- --test-threads=1`; build tail may be empty or `--target wasm32-unknown-unknown`. No features/-F/workspace/package/config/filter expansion is supported. Kind must agree with argv. A cargo-test exit0 with zero reported passing cases refuses test-scope success. Generated-check kind requires an admitted absolute tool, committed script in required_inputs, nonempty required historical pins, and --check. It delegates semantic freshness to that separately reviewed script; the runner seals declarations but does not automatically prove the script consumed its pins.

Cargo requires explicit declared RUSTC and workspace CARGO_HOME. Candidate Cargo configs, configs in ancestors above the checkout, and CARGO_HOME configs conservatively refuse; absence is rechecked in every snapshot. Unmodeled workspace/inheritance/patch/replace, default/dependency feature activation, proc macros, build scripts, registry dependencies, outside-target/local paths or missing locks remain unsupported, never silently complete. This strict subset is deliberate. General Cargo metadata/sysroot/registry closure belongs to RR16b rather than an incomplete regex dependency engine.

## Source seal and receipt meaning

Every candidate Git-tracked regular file is a conservative repository-input superset, including runner/manifests/locks/tools/tests/backend/porting fixtures/generated data. New untracked or ignored candidate files refuse. Gitlinks and tracked symlinks refuse explicitly; Git executable mode is checked from the owner execute bit. Committed blob hashes/modes are batched/cached once per candidate while current disk bytes, memberships, HEAD/index, historical pins, declared tools/external files, admission and Cargo-config absence are checked before and after every command and finally. Raw and portable stdout/stderr are retained with independent hashes; each command records exact declared argv/kind/manifest, UTC, exit/signal/timeout, observed summary lines and before/after seals. Admission's exact original bytes are retained separately.

Success is only `SELECTED_CHECKS_PASSED`, always `full_qualification:false`, even when every discovered manifest is selected. No generic/full integration PASS route exists. Inventory distinguishes selected, held, unsupported, unselected and resumed-prefix manifests; command records and not_run_commands distinguish selected from executed. Nonzero, missing case observations, drift, unsupported scopes and timeout fail/refuse and retain receipt/streams. Resume never borrows earlier passes. Admission/path failure before an authorized evidence directory exists is an outer caller refusal, not permission to write elsewhere.

The full-Git seal describes the exact implementation candidate/epoch. Later evidence-only commits are not falsely described as having the same complete Git tree; root binds tested source blobs and exact candidate separately. External/toolchain completeness is declaration-only. Before/after hashes attest quiescent observations, not every read, arbitrary build/runtime I/O, hostile transient change-then-restoration, or a sandbox. The isolated candidate must have no other writer. Required historical declarations and generator semantics remain separately reviewed authority. Neither this mechanism nor selected Cargo success substitutes for the complete composed RR16b matrix or RR17 CI gates.
