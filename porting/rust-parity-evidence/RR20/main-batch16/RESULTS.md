# RR20 model-only history adoption on main prerequisites

This change adopts the complete existing model-history policy after pure containment and RR04. The library equals the original donor after removing only its held default-off export block. All original transaction code and canonical output contracts remain in place; no UI, borrowed-summary, raw/factory or initializer source is imported. The two-file source delta has 276 library additions/15 removals, including 42 private-test lines, plus 303 integration-test lines.

Fresh checks pass 77 model cases, formatting, all-target Clippy and WASM checking. The new cases are ten integration tests plus one private exhaustion test; earlier prose describing eleven integration tests is retained historically and is not reused as a count. Foreign, poisoned, stale, no-op, failed-publication and exhausted-revision paths preserve their required state. Combined retention entry/charge bounds, exact numeric spellings, typed availability, redo invalidation and rollback remain covered by their named cases.

The unchanged external observer ran 72 fresh release processes: 1,000/4,096 elements × 64/256 commits × two modes × two warmups and seven measurements, alternating mode order. All explicit cancellation checks preserve committed data and return requested live allocation to its prior value. On the 4,096-element/256-commit fixture, baseline retained requested live bytes are 1,500,287,745; repaired bytes are 58,377,296. Separate external peak RSS ranges are 1,706,120–1,706,636 KiB and 95,032–95,568 KiB. Those values describe this API/process workload, not a universal memory limit, allocator overhead, exact copying, leak freedom or GUI latency. Raw edit/undo/redo/cancel timing ranges remain in the summary without p95 or native speed claims.

The default policy permits at most 64 retained entries and a 128-MiB capacity charge across both stacks. Actual retained counts are 40 on the 1,000-element fixture and nine on the 4,096-element fixture. The capacity charge is deliberately conservative and is not heap/RSS; current documents, open transactions and temporary cloning are outside it. Begin still clones twice and apply clones staged data. Cancellation is explicit synchronous transaction cancellation, not cooperative preemption.

Available-redo refusal at revision exhaustion and isolated multi-entry ByteBudget/tiny-policy deque overhead remain coverage distinctions. The full RR20 obligation still requires actual renderer/history callers, visible retention policy under RR19 and the admitted #130 main composition. No current main production renderer uses this model. Old browser evidence stays attributed to its old composition. Native semantic history, durable project workflow, UI usability and full feature acceptance remain open.
