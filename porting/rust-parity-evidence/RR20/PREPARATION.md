## Retention contract

Default is **64 total undo+redo entries and 128 MiB retained-capacity charge**, independently enforced. `HistoryLimits::new` refuses policies above either default maximum; either zero disables retention. Current document, open transactions, input fixtures, temporary validation and allocator overhead are outside this policy. These numbers are **not a 128 MiB heap/RSS guarantee**.

Charge counts each visited Value header; actual String/key capacities; actual Vec capacity times Value size; object allowance of 1024 bytes plus key/value headers and 128 bytes per occupied key; actual combined VecDeque capacities times HistoryEntry size. Array element headers are deliberately counted again during traversal. Object allowance is a conservative policy for the qualified BTreeMap backend, not a portable allocator proof. Number's opaque string capacity is replaced by an exact-token owned string once at construction/changed commit and that capacity is charged; token spelling and ordinary marker-object structure remain unchanged. Arithmetic saturates; traversal stops beyond publication depth128. Number compaction does not parse a generic Value or reinterpret private keys. Other serde_json backends/features need separate qualification.

Every successful commit and history move trims the combined histories until both limits fit. It discards oldest undo first, then farthest redo. Consequently undoing a large current document can discard older undo entries before eventually discarding an oversized redo snapshot; restored current data remains valid. Empty buffers are released after eviction; surviving empty buffers are still charged. Oversized entries are dropped; commits still succeed and `HistoryState` reports counters, availability/boundary and last truncation reason. Last reason and cumulative undo loss persist across later operations; successful branch commits discard redo and reset its loss counter. Limit changes alter metadata, not document revision.

Undo/redo move owned Documents and cached charges; neither clones model snapshots. Begin still makes two full document clones and each transaction operation still clones its staged document. Their cost is measured and remains an explicit optimization gap. Owner/revision checks, poisoned transactions, noops, publication refusal and cancellation preserve history. At u64 revision exhaustion, changed commit returns typed RevisionExhausted; undo/redo refuse before mutation, while a noop remains a noop.
