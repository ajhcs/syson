## Migration authority and budgets

Inspecting `Literal::root()` before `into_value` replaces both former serde namespace visitors, including their unsafe first-value materialization. LastWins preserves final values and first decoded-key positions (including escaped-equivalent keys); root `ns` duplicates keep their final object just as before. Inspection Value remains lexically ordered and is not namespace wire authority. Existing `Prepared::to_json` retains namespace order for participant re-entry.

The selected resource remains at most 1 MiB input/output, 65,536 values and old root-zero maximum depth 64. RR01 root-one depth 65 preserves that depth boundary. A 65,536-key guard is redundant for valid JSON under the physical value cap; conservative scalar charge at most 2 MiB covers twice the bounded raw input. The explicit tightening counts *all physical source values/keys*, including overwritten duplicates, before owned materialization, where old generic Value parsing collapsed duplicates before its DOM count. RR24 tests exercise exact physical cap and +1 as well as unchanged ordinary DOM edges. This is selected migration admission, not native project capacity.
