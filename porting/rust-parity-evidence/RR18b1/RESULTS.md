## Behavior and original counterexample

The actual public Canvas baseline test reaches a 2,097,152-byte single allocation request while refusing quoted geometry. The test tracks only apply after preparing a valid small current frame and a larger opaque model; assertions after that failure were not reached on the baseline. Final code passes the same allocation/refusal/history case with no request above 65,536 bytes, then executes the prior-state/history assertions. This is an allocation-request bound in that window, not aggregate heap/RSS or whole-app memory acceptance.

Borrowed geometry fields now go through the same count/emit protocol. Raw file and JSON-string-wrapped ABI size (+2048-byte envelope) are both checked before one exact reserve request. The old compact field order, floating-point/null/Option/string spelling and model binding remain exact. Immutable Frame model and admitted wire buffers share Arc ownership in clones/history; failed admission cannot publish a partial cache. First requests still allocate a bounded canonical model key, independent requests do not intern equal keys, and explicit export owns one String copy. A wire cache per frame can increase retained memory; existing 32-entry canvas history remains unchanged. No global memory guarantee follows.

Frame identity compares canonical RR04 writer bytes into a nonallocating output sink. This still traverses/serializes the document; it is not zero CPU. Empty frame/history paths avoid pointless model output. The closed App dispatch removes before/after JSON output for known staging/selection/canvas actions and invalidates canvas only for current committed mutation cases. Future committed actions must join that set. Normal render/navigation/scalar helpers and their intermediate allocation remain unchanged.
