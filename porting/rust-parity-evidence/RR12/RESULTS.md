# RR12 storage field admission before copies and fetches

Rust checks every borrowed Create/Update name against 4096 UTF8 bytes before cloning or staging protocol output. SQLite load validates generation and bounded metadata in the same RR11 transaction before selecting payload text. Row type, byte count, read-only flag and revision checks precede payload fetch. A conservative escaped-response bound precedes JSON output. Each actual connection applies SQLITE_LIMIT_LENGTH at the 1 MiB document limit plus 8192 bytes; maximum valid rows remain usable. Schema projections and generation strings are capped before Python materialization. Existing generation/CAS/rollback behavior remains intact. Root's one inherited RR11 test-proxy method forwards setlimit to the actual connection; it bypasses no guard.

SQLite byte-length admission explicitly requires UTF8 database encoding. Fresh candidate databases already use UTF8; externally supplied UTF16 v2 candidates now refuse unchanged, including offline epoch renewal. No schema/version rewrite is performed. This is an explicit candidate constraint. The provisional Python bridge remains pending the B07 Rust replacement. Logical field guards and Python allocation measurements do not bound SQLite C-engine allocation, RSS or hostile database-parser memory.

Baseline #89 reproduces a 2,097,152-byte proportional name allocation (2,098,260 additional live peak), and accepts an oversized stored name. The repair refuses the borrowed name with the regression's 64 KiB allocation bound, refuses corrupt fields unchanged, and observes zero payload SELECTs with returned metadata strings at most 1024 bytes and bounded error output. Maximum valid content/name and a heavily escaped response remain admitted. Whole-bridge refusal probes allow 9 MiB Python peak because the unchanged stdin read(LIMIT+1) preallocates an 8 MiB buffer. The original incorrect 256 KiB expectation failed at 8,390,218 bytes; those failures remain visible. The strict zero-payload-fetch, string and response checks were not relaxed. The escaped-response probe allows 32 MiB Python peak and an 8 MiB protocol response cap; none is a process RSS claim.
