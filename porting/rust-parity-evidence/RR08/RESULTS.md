# RR08 bounded AST rollback and scalar copy work

Whole-State transaction snapshots are replaced by an undo journal for changed fields/array lengths/kinds, frames/datatypes, CST entries and allocations. Nested successes retain undo until the outer transaction resolves; reverse-order rollback restores state while IDs/work remain spent. Selected text, datum, kind/error-kind and containment-property copies charge work before reservation and poll cancellation in bounded UTF8 chunks. Default construction limits are unchanged, but counting copied bytes deliberately makes some workloads refuse earlier. Root updates the inherited three-unit expectation to seventeen: transaction one plus two allocations of one operation and seven Element bytes. Diagnostic-only unsupported(&self) strings and caller-owned Lexeme/Datum/Arena clone APIs are not globally bounded by this change; panics remain outside the rollback contract.

The finite parser is tested separately because it does not invoke that synthetic F12 path. These are selected debug requested-layout traffic observations, not live memory, allocator overhead, RSS, native ratios, general complexity or latency SLAs.
