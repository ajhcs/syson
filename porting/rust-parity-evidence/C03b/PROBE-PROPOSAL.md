# C03b selected recipe verification proposal

The input-only packet contains three typed-project cases: combined legacy semantic/diagram data; a foreign-first namespace with pending semantic removals; and an unrelated representation with independent unknown stamps. Assertions live in the ten Rust integration tests; there are no native observations yet for this consuming recipe.

The first case executes actual B25b -> B25a -> B25c, Document admission, B01 semantic1600/diagram1700 and B25d. It retains node/semantic identities, note text, unknown values and a large integer. On its own, B01 refuses the old object-valued reference fields, so this is a real consumption path rather than metadata-only validation.

Root checks should freeze the exact four-participant prerequisite snapshot, new crate/manifests/lock and packet, then run focused tests, formatting and all-target Clippy. Required refusal probes include every later future watermark before any resolver call, a late Document failure, a late B25d nested-array refusal, resolver failure and actual B01 expansion limits. Keep original failures and re-run only affected checks.

Selected native follow-up can compare the semantic pre-migration segment with the existing source-compiled b/a/c oracle and the final control segment with the B25d callback/service oracle. Input namespace order must be identical. Their selected comparisons do not establish a native global history/persistence transaction or qualify B01's complete native framework lifecycle. No source-derived expectation may be labeled as observed native output.

For a repeatable modest capacity probe, derive 256/1024/4096-node inputs within candidate byte/value limits, record exactly which sizes are admitted, and measure preparation plus peak RSS and resolver-call counts on identical frozen fixtures. Record medians/p95 over a stated warm/cold sample protocol before optimization; no timing, native capacity or browser responsiveness claim is made by these tests.

The typed and wire snapshots are private until complete success. The caller owns durable publication and read-only resolver effects; this crate cannot undo a resolver's external side effects. C03/C06/C07, source/artifact closure, host/UI, SQL, migration-history activation and broader feature acceptance remain open.
