# C01g results

The Rust catalogue admits the actual 94-file corpus (36 KerML, 58 SysML; 20,874,941 bytes) and exports 109,673 physical nodes. Root's release CLI compared every stored node-ID/semantic-ID/class/name tuple with the actual native resource set, keyed by resource URI and serialized node ID. The only class projection pairs raw `sysml:EClass` with native namespace `http://www.eclipse.org/syson/sysml`; traversal order, pointer order, payload fields and fragment behavior are not claimed equivalent.

`captures/c01g-01` passed all nine integration tests, formatting, Clippy, and debug/release builds, with all 12 captured input hashes unchanged. The tests cover genuine files and native identity observations, domain/resource collisions, no fallback, raw tokens/Unicode and JSON pointers, duplicate keys, late atomic refusal, byte/depth/path limits and the real consuming CLI. No source was changed after this capture. The separate source peer review accepted those exact hashes; the reviewer did not execute tests.

`library-native-01` observes the actual default configuration, resource set, classpath paths, URIs and ID fields. It freezes 316 input hashes, including the official classpath-ordered dependency JARs and observer/compiler/runtime inputs. Its 94 loaded resources and 109,673 objects coexist with 12,162 diagnostics. `library-diagnostics-02` adds the previously unobserved typed message/location/line/column details in a fresh resource set; it does not replace the original identity capture. All errors are `org.eclipse.sirius.emfjson.resource.PackageNotFoundError`; there are zero warnings. The compact summary retains all 94 resource metadata/error counts and representative exact messages. These facts block clean-load and resolved-reference-closure claims; no native fix was attempted.

Native root Namespace objects accept their node-ID lookup and refuse their semantic-ID lookup; the observed LibraryPackage samples accept both. The Rust semantic-ID index locates stored metadata for every physical node, including those roots. It deliberately does not claim native `Resource.getEObject`, URI-fragment aliasing or semantic-query equivalence. No identity fallback, URI generation or ID normalization is performed.

`library-cli-01` passed the full corpus and before/after 98-input identity checks. One release process observed 0.34 seconds wall time and 150,928 KiB peak RSS while reading, indexing and writing a 49,195,840-byte index. `time.txt` is the original observation. This is one whole-process sample, not constructor latency, a percentile/SLA, a native/Rust speed ratio or a wider capacity claim. The same eleven registry name/version/checksum tuples are reused; `registry.json` records the exact comparison.

The full 94-file corpus, 30,199,550-byte native identity output, 3,037,471-byte diagnostic output and 49,195,840-byte Rust index remain external at the hash-addressed locations in `external-artifacts.json`. Original wrappers, commands, receipts, stdout/stderr and RSS output are copied without relabeling. The original proposed Java source remains separate from root's executed bounded CREATE_NEW observer. Source resource bytes equal pinned Git and shipped artifact bytes as recorded in `source-inventory.json`; this is not an independent full application build.
